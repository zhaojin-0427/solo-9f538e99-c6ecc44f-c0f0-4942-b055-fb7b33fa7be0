# 变星相位补拍计划（单星）

Flask + SQLite 小工具：按 UTC 日维护有效曝光，把时段折进一个周期，
用半开秒区间列出**覆盖不足两日**的相位，供下一晚补拍参考。

## 启动

```bash
docker compose up --build   # 访问 http://localhost:8000
```

本地开发：

```bash
pip install -r requirements.txt
python run.py               # 或 gunicorn --bind 0.0.0.0:8000 "app:create_app()"
```

SQLite 数据库路径用环境变量 `STAR_DB` 指定（compose 中为 `/data/star.db`，挂在命名卷上）。

## 用法

1. **定参数**：零相位 UTC 整秒时刻 `t0`（整数秒或 `2026-11-23T00:00:00Z`）+ 固定周期 `P`（正整数秒）。已有数据时须先清空才能重设。
2. **上传 / 整日替换 / 撤下**：选 UTC 日，粘贴 CSV（每行 `start,end`，当日整数秒或 `HH:MM:SS`，**含起点、不含终点**），提交即整日替换；**空表 = 撤下当日曝光**。
3. **查询**：列出覆盖不足两日的相位（半开秒区间）；可**临时排除最多两日**（只影响本次查询，不改数据）。
4. **最少观测日计划**：输入半开相位区间 [起, 止) 与所需覆盖日数（1～2），从已有曝光日中选
   **不超过 20 个候选日**，求让每个相位至少由所填数量的**不同 UTC 日**覆盖的**最少日期**，并列出各日贡献；
   先**预览**再**确认保存**。
5. 页面显示**单次查询读取**和**单次更正写入**的全局覆盖记录数（含"最近一次"汇总）。

## 数据模型

- `config`：`t0`（整数秒）、`period`（正整数秒），单行。
- `exposures`：`(day, start_sec, end_sec)`，当日秒，半开 `[start, end)`。
- `coverage`（全局覆盖）：相位圈 `[0, P)` 上互不相交的 `(ph_start, ph_end, days)`，
  `days` = 覆盖该区间的**不同 UTC 日数**（同一日对同一相位只计一次：当日曝光先折相取并集，再计入）。
- `day_versions`：每个 UTC 日一行 `(day, version)`，版本号单调递增；每次成功的整日更正
  （含空表撤下、含内容未变的再次提交）都在同一事务内 +1，用于计划确认时判定预览是否过期。
- `plans`：已保存的最少观测日计划，单行 `id=1`，含目标区间、所需日数、选中日（有序 JSON）、
  候选日及其预览时版本、各日贡献区间、保存时刻。
- `plan_preview`：最近一次预览的快照（单行 scratch 表），与会话中的 `preview_id` 配对；
  确认成功后删除，新预览覆盖旧预览。

## 关键语义与实现

- **折相**：曝光 `[s,e)` 按 `(t - t0) mod P` 折进相位圈；跨周期边界拆成两段；长度 ≥ P 覆盖整圈。
- **更正**（`core.replace_day`）：一个 `BEGIN IMMEDIATE` 事务内——只读当日曝光与**和受影响区域相交**的覆盖记录；
  受影响区域 = 旧当日相位集 ∪ 新当日相位集；只重写该区域内的覆盖（区域外碎片原样补回，未相交的行不动）；
  曝光与覆盖**同事务生效**；任何失败 `ROLLBACK`，**沿用原结果**。
- **查询**（`core.query_insufficient`）：一个只读事务内取全部全局覆盖 + 排除日的当日数据，
  **整次结果取自同一已提交状态**；有效天数 = 全局天数 − 覆盖该相位的排除日数，输出 < 2 的合并区间。
- **计划预览**（`core.preview_plan`）：一个只读事务内读取配置、最多 20 个候选日（按 UTC 日升序）
  的曝光与当日版本，折相并裁剪到目标区间，**整次结果取自同一已提交状态**；随后在单独事务里把
  快照写入 `plan_preview`（只写派生数据，不碰曝光/覆盖/已存计划）。
- **最少日求解**（`planning.find_min_days`）：端点事件扫描贪心，只在区间端点处判断与计数，
  **不随区间秒数增长**。k=1 用经典最少区间覆盖（覆盖最左缺口、选右端点最远者）；
  k=2 用双重覆盖变体（新区间须接上已满足的双覆盖前缀 `reach`，再选右端点最远者）。
  单元测试对 400 个随机小实例与暴力枚举（全部子集）对拍，解的个数与可行性完全一致。
- **计划确认**（`core.confirm_plan`）：`BEGIN IMMEDIATE` 单事务内读取预览快照、配置、候选日版本、
  选中日曝光并完成写入，**确认本身只读取一个已提交状态、不重新求解**。任一候选日版本与预览时
  不同即拒绝（即使内容改回原样：版本只增不减）；参数变化、预览被新预览取代、预览无解同样拒绝；
  任何异常都 `ROLLBACK`，**无解、过期、写入失败都不改旧计划**。成功保存的就是预览所见的数据版本。
- **不逐秒展开**：折相、区域重算、查询、计划求解全部是区间事件扫描（端点排序 + 二分定位），
  代价只取决于区间条数。测试用 `P = 10^12`（应用级）和 `P = 10^15`（单元级）验证瞬时完成。

## 已实现

- 零相位时刻 + 固定周期的设置与锁定（有数据时须先清空）。
- 按 UTC 日上传 / 整日替换 / 空表撤下曝光（CSV 支持整数秒与 `HH:MM:SS`，`#` 注释，可选表头）。
- 折相、同日同相位只计一次、全局覆盖的增量维护（只动受影响区域）。
- 覆盖不足两日的相位查询（半开秒区间），可临时排除最多两日。
- 最少观测日计划：半开相位区间 + 所需覆盖日数（1～2），候选日上限 20，端点扫描求最少日期，
  列出各选中日在目标区间内的贡献相位与总时长；预览后确认保存，页面回显当前已保存计划。
- 预览/确认两阶段：预览快照（含候选日版本）落服务端单行表；确认时核对版本，
  预览后任一候选日被更正（即使改回原样）即拒绝并要求重算；无解/过期/写入失败不动旧计划。
- 页面显示单次查询读取 / 单次更正写入的全局覆盖记录数，以及"最近一次"汇总。
- 更正原子性（曝光与覆盖一起生效，失败沿用原结果）；查询与计划预览单事务一致性快照。
- 全程区间算术，不逐秒展开。

## 已实测

- `pytest`：**55 项全部通过**（`tests/test_intervals.py` 15 项区间单元 + `tests/test_app.py` 14 项
  端到端 + `tests/test_planning.py` 10 项计划算法单元 + `tests/test_planning_bruteforce.py` 2 项
  暴力对拍（400 个随机实例）+ `tests/test_plan_app.py` 14 项计划端到端），覆盖：
  - **跨周期曝光**（如绝对 `[86900,87200)` 折成相位 `[900,1000)∪[0,200)`）建成的全局覆盖与手工推导逐行一致；
  - **整日替换前后的缺口**：三日建成后缺口 `[50,950)`，替换 1970-01-02 后变为 `[50,1000)`，
    受影响区域外记录 `(600,700,1)` 的 `id` 不变（证明只更新受影响覆盖），本次更正写入 8 条（删 5 + 插 3）；
  - 空表撤下、同日同相位只计一次、半开相接无缺口、排除 0/1/2 日、失败沿用原结果、
    未设参数时上传干净失败、有数据时锁定参数、页面记录数显示、`P=10^12` 瞬时完成；
  - **计划贪心最优性**：k=1/k=2 的最少个数、半开边界、多片段候选日、无解缺口、超大坐标瞬时完成，
    并与暴力枚举在 400 个随机实例上逐一比对（个数最少 + 每点覆盖数达标）；
  - **计划网页全流程**：预览→确认保存并直接读库核对、k=2 需两个不同 UTC 日、
    预览后更正候选日（**即使改回原样**）确认被拒且旧计划不动、更正未选中候选日也拒、
    更正非候选日不影响、无解预览禁止确认且保留旧计划、触发器注入写入失败后回滚旧计划不变、
    20 候选上限按 UTC 日截断、参数/区间校验、无预览确认被拒、新预览作废旧预览、重置清空计划与版本、
    每次更正版本号单调 +1。
- 用 gunicorn（与 Dockerfile 相同 CMD）起真实服务，curl 走通"设参 → 三日上传 → 查询 →
  整日替换 → 计划预览（k=1/k=2）→ 确认保存 → 更正后改回原样确认被拒 → 重算确认 →
  无解确认被拒且旧计划不动 → 非法输入报错 → 空表撤下"全流程，结果与测试一致；直接读库核对终态正确。
- `docker-compose.yml` 通过 YAML 结构校验；`requirements.txt` 中依赖已实际安装运行。
