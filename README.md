# 变星相位补拍计划（单星）

Flask + SQLite 小工具：按 UTC 日维护有效曝光，把时段折进一个周期，
用半开秒区间列出**覆盖不足两日**的相位，供下一晚补拍参考。

## 启动

```bash
docker compose up --build   # 访问 http://localhost:8000
```

本地开发：

```bash
pip install -r requirements.txt
python run.py               # 或 gunicorn --bind 0.0.0.0:8000 "app:create_app()"
```

SQLite 数据库路径用环境变量 `STAR_DB` 指定（compose 中为 `/data/star.db`，挂在命名卷上）。

## 用法

1. **定参数**：零相位 UTC 整秒时刻 `t0`（整数秒或 `2026-11-23T00:00:00Z`）+ 固定周期 `P`（正整数秒）。已有数据时须先清空才能重设。
2. **上传 / 整日替换 / 撤下**：选 UTC 日，粘贴 CSV（每行 `start,end`，当日整数秒或 `HH:MM:SS`，**含起点、不含终点**），提交即整日替换；**空表 = 撤下当日曝光**。
3. **查询**：列出覆盖不足两日的相位（半开秒区间）；可**临时排除最多两日**（只影响本次查询，不改数据）。
4. 页面显示**单次查询读取**和**单次更正写入**的全局覆盖记录数（含"最近一次"汇总）。

## 数据模型

- `config`：`t0`（整数秒）、`period`（正整数秒），单行。
- `exposures`：`(day, start_sec, end_sec)`，当日秒，半开 `[start, end)`。
- `coverage`（全局覆盖）：相位圈 `[0, P)` 上互不相交的 `(ph_start, ph_end, days)`，
  `days` = 覆盖该区间的**不同 UTC 日数**（同一日对同一相位只计一次：当日曝光先折相取并集，再计入）。

## 关键语义与实现

- **折相**：曝光 `[s,e)` 按 `(t - t0) mod P` 折进相位圈；跨周期边界拆成两段；长度 ≥ P 覆盖整圈。
- **更正**（`core.replace_day`）：一个 `BEGIN IMMEDIATE` 事务内——只读当日曝光与**和受影响区域相交**的覆盖记录；
  受影响区域 = 旧当日相位集 ∪ 新当日相位集；只重写该区域内的覆盖（区域外碎片原样补回，未相交的行不动）；
  曝光与覆盖**同事务生效**；任何失败 `ROLLBACK`，**沿用原结果**。
- **查询**（`core.query_insufficient`）：一个只读事务内取全部全局覆盖 + 排除日的当日数据，
  **整次结果取自同一已提交状态**；有效天数 = 全局天数 − 覆盖该相位的排除日数，输出 < 2 的合并区间。
- **不逐秒展开**：折相、区域重算、查询全部是区间事件扫描（端点排序 + 二分定位），
  代价只取决于区间条数。测试用 `P = 10^12`（应用级）和 `P = 10^15`（单元级）验证瞬时完成。

## 已实现

- 零相位时刻 + 固定周期的设置与锁定（有数据时须先清空）。
- 按 UTC 日上传 / 整日替换 / 空表撤下曝光（CSV 支持整数秒与 `HH:MM:SS`，`#` 注释，可选表头）。
- 折相、同日同相位只计一次、全局覆盖的增量维护（只动受影响区域）。
- 覆盖不足两日的相位查询（半开秒区间），可临时排除最多两日。
- 页面显示单次查询读取 / 单次更正写入的全局覆盖记录数，以及"最近一次"汇总。
- 更正原子性（曝光与覆盖一起生效，失败沿用原结果）；查询单事务一致性快照。
- 全程区间算术，不逐秒展开。

## 已实测

- `pytest`：**29 项全部通过**（`tests/test_intervals.py` 15 项单元 + `tests/test_app.py` 14 项端到端），覆盖：
  - **跨周期曝光**（如绝对 `[86900,87200)` 折成相位 `[900,1000)∪[0,200)`）建成的全局覆盖与手工推导逐行一致；
  - **整日替换前后的缺口**：三日建成后缺口 `[50,950)`，替换 1970-01-02 后变为 `[50,1000)`，
    受影响区域外记录 `(600,700,1)` 的 `id` 不变（证明只更新受影响覆盖），本次更正写入 8 条（删 5 + 插 3）；
  - 空表撤下、同日同相位只计一次、半开相接无缺口、排除 0/1/2 日、失败沿用原结果、
    未设参数时上传干净失败、有数据时锁定参数、页面记录数显示、`P=10^12` 瞬时完成。
- 用 gunicorn（与 Dockerfile 相同 CMD）起真实服务，curl 走通"设参 → 三日上传 → 查询 →
  整日替换 → 排除日查询 → 空表撤下 → 非法 CSV 回滚"全流程，结果与测试一致；直接读库核对终态正确。
- `docker-compose.yml` 通过 YAML 结构校验；`requirements.txt` 中依赖已实际安装运行。
